zObjectMesh / zFnMesh topology audit

8 October 2026 · Updated implementation review · 280 active definitions inventoried

What the audit establishes

The mesh object already stores positions, face offsets, face corners and unique edges in flat arrays. Full halfedge topology is a lazy secondary backend. Most bulk zFnMesh queries already use flat storage. smoothMesh is already flat; halfedge removal is not the explanation for its measured C++ cost.

Coverage: all 6 zObjectMesh definitions, all 120 zFnMesh definitions/overloads, and all 154 mesh iterator definitions in the current source. Constructors, destructors and protected helpers are included. Storage lifecycle, flat storage construction, shared query helpers, WASM smoothing/export and existing smoke tests were also inspected. Commented-out old implementations are excluded.

Updated after the first iterator patch: edge center/length and face center/corner count/triangulation/constant offset now use flat data; updateNormal benefits through those queries. The mathematical routines and public signatures are preserved. Geometry-only queries now accept nonmanifold flat meshes; explicit halfedge queries still reject them. Directed edge vectors, position lookup, face-local curvature and variable offsets now use flat data without materializing topology. Existing backend identity remains authoritative when already present. Ordered adjacency/ring migration remains incomplete; explicit topology editing retains the backend. Volume now initializes its triangle counter and uses flat positions, with signed/absolute/automatic and nonmanifold regression coverage. Smoothing, curvature workspace and bounds changes are documented in the optimization results. Performance candidates below remain hypotheses until measured; this patch does not claim a subdivision or FPS speedup.

Why apparently simple queries become expensive

  1. Mutable get() builds topology and marks the flat representation dirty even when the caller only reads it.
  2. The next flat read synchronizes topology back into arrays; the next topology query can itself synchronize first. Alternating calls can copy/rebuild repeatedly.
  3. edit() discards topology for connectivity changes, position/attribute changes and mutable-pointer requests alike.
  4. Topology construction validates edge use/orientation, copies connectivity/positions/attributes and builds endpoint maps. Synchronization compacts active vertices/faces, rebuilds unique edges and remaps edge attributes.

Do not merely change every get() to its const overload: it prevents false dirty marking but still materializes full topology and still rejects some input meshes. Use flat geometry first; retain const topology reads for genuinely topology-dependent queries.

Subdivision and bridge evidence

smoothMesh now constructs contiguous corner-edge records sorted by endpoint/face/corner, retaining lexicographic edge-point numbering and sum order. Per-corner point indices remove repeated output lookups. Internal move installation avoids position/connectivity copies. See latest subdivision and viewer results. The original vertexNeighbors allocation has been removed, per-vertex face sums and inline edge-face records reduce small allocations, and newPositions now reserves its final size; output counts/corners are already reserved. At the iteration end, internal storage installation moves arrays and validates/rebuilds unique edges/default attributes, then computes normals after the final internal division (the original implementation calculated them after every division).

WASM smooth now exports the final normals without a redundant recomputation (the empty-mesh path is retained). Render export now reads flat arrays by reference and reuses cached unique-edge direction, use counts and weights, removing those three ordered maps. Face and vertex normal calculation is fused while preserving accumulation order. Verified before/after results are in normals/export results. This is separate from the subdivision formula.

Earlier isolated profiling medians across three trials for eight roundtrips: upload 368.8 ms; smoothMesh 718.0 ms; bridge normals/export 1343.8 ms; JS readback 58.2 ms. The smoothMesh timer includes internal storage rebuilds and normals, not just arithmetic. Independent phase medians need not sum to the median total. The earlier profiled runtime eighth-step C++ call was 1669.2 ms, which includes export. Thus calling that entire 1.7 s the subdivision algorithm overstates the evidence.

Eight divisions in one profiling call took 2241.2 ms median versus 2466.5 ms for eight roundtrips (about 9% in this small sample). Exact topology/position parity was checked earlier. This supports batching, but does not establish a universal speedup or 500,000-polygon interactivity.

Other substantial optimization opportunities

Bulk principal curvature already uses flat data. Its getKRingVertices helper now reuses a V-sized stamp array and neighborhood capacity across queries; this removes the previous repeated allocation/clearing. The queue and numerical fitting are unchanged. The measured small-grid timing is in the optimization results. Preserve local neighborhood ordering and numerical fitting.

Dihedral queries and edge data rebuild edge-face incidence. Cache or reuse that incidence behind connectivity revisions if profiling confirms repeated queries. Topological Laplacian is a cotangent computation and remains ring-dependent. Vertex areas consumes halfedge-indexed edgeCenters; unique-edge IDs are not interchangeable.

Compatibility and verification gates

  • Golden parity on cube, open grid, triangles, quads, concave polygons, degenerate/isolated vertices and mixed faces. Check positions, topology, normals, triangles, edge directions/IDs, colors, weights, boundary sentinels and exceptions.
  • Flat storage accepts meshes rejected by topology construction. Removing an accidental topology dependency may expand accepted inputs; explicitly decide and test this behavior. The current manifold guard checks edge incidence and consistent orientation, not full vertex-fan manifoldness.
  • After topology edits, sync compacts active entities while retaining the topology backend and marking it clean. ID alignment between compact arrays and topology deserves targeted tests before changing caching; this is a static risk, not a demonstrated runtime failure.
  • Test alternating topology read → flat read → attribute edit → topology read; instrument topology builds/syncs to prove pure flat queries never build topology. Focused smoke tests now assert that lookup, vector, local curvature and offset queries leave topology uncreated, while explicit halfedge access materializes it. Ordered adjacency migration still needs its own identity and ordering coverage.
  • Test object copies with dirty topology and mutable pointer lifetimes. Preserve public signatures, sketches and the current attribute reset behavior of storage set.
  • Benchmark warm repeated trials and report median/tail time plus peak WASM memory. Measure upload, subdivision arithmetic, edge/storage rebuild, normals, export, JS readback and viewer/history/render separately.
  • Eight cube divisions produce 393,216 quads; nine produce 1,572,864. Add an exact ~500,000-face grid benchmark, boundaries and a representative mixed mesh. Polygon count alone does not bound triangle count or render/export memory.
  • For implementation: native Release build and ctest; rebuild WASM for bridge/kernel changes; npm run build after each viewer extraction/change. Update roadmap checkboxes only after verified work.
