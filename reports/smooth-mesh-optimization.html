Changes

  • smoothMesh: remove unused neighbor lists, ordered vertex-face sums, inline first two edge-face IDs plus total incidence, reserve output positions, calculate final normals once per batched call
  • getPrincipalCurvatures: reuse K-ring visit stamps and neighborhood capacity
  • getBounds: avoid position-array copy except aliased output fallback, retain existing sentinels
  • zItMeshFace::getVolume: initialize supplied/generated triangle count, migrate utility and position access to flat storage

Does only necessary topology build now?

Incomplete migration. smoothMesh, bulk principal curvature, bounds and face volume do not build topology from flat data. Remaining avoidable dependencies include vertexExists position lookup and some iterator geometry/direction queries. Explicit halfedge APIs and local topology edits still build the lazy backend; reads can synchronize previously edited topology.

Verification and limits

  • Isolated native Release build with optional TinyUSDZ disabled; focused geometry CTest passed
  • Golden triangle ordering, signed/absolute/auto volume, nonmanifold quad volume, mixed open mesh batch-vs-step smoothCorner false/true parity, zero divisions, bounds/raw-alias/empty sentinels
  • Native before/after cube steps 1-8, batch 8, curved-grid principal curvature and subdivision to exactly 500000 quads: all output digests identical
  • Final WASM rebuild passed; three cube trials through eight divisions, 12 exported buffers byte-identical at all 27 stages; optimized runtime installed in viewer with original runtime backed up under wasm/tmp/smooth-runtime-install-before.
  • Default Release preset remains blocked by optional pinned TinyUSDZ checkout. USD IO and native OpenGL display runtime verification limitations remain as recorded in mesh-iterator-flat-verification.json.
  • No ordered-map/hash-map redesign, storage move installation, bridge normals/export optimization or UI changes in this patch.
  • The 500000-quad result is a native kernel workload, not evidence of end-to-end viewer interactivity.
  • The full eighth-step WASM call remained about 1.82 seconds in this sample despite the native kernel gains. Bridge normals/export remain unchanged; no end-to-end viewer speedup is established.
