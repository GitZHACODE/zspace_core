Findings: verified source versus hypotheses

G01: Read-like topology access triggers full flat synchronization

verified-source · proposed priority 1

buildTopology synchronizes edgeListDirty before checking a clean existing backend. Mutable get marks edgeListDirty=true. Every following get can therefore walk V/E, allocate vertexMap and new arrays and install attributes. Halfedge isActive/getId/end/size and nested navigation use this mutable overload; loops can multiply full-graph synchronization by traversal length. Severity/scaling follows source; time dominance remains a native measurement hypothesis.

G02: Synchronization compacts active IDs while keeping the backend

verified-source · proposed priority 1

syncEdgeList skips inactive vertices/edges and invalid endpoints, renumbers flat endpoints, then leaves topologyDirty=false with original backend IDs/links. Vertex/edge iterator activity uses flat index ranges. Changing read intent can change when compaction happens; preserve activity and ID observations before optimizing. G04: Flat lookup and backend maps have different contracts

verified-source · proposed priority 3

Flat position search is first-match factorized distance; flat unordered endpoint lookup is first edge. Backend rounded string maps overwrite duplicates; directed self-edge key is overwritten by the symmetry entry. Cache public flat lookup semantics, not mesh last-match semantics. Failed scalar halfEdgeExists returns without resetting outHalfEdgeId; preserve it.

G05: Ordering depends on geometry, angle ties and stored fan seed

verified-source · proposed priority 3

Topology fan order follows angular sort and prev.sym, beginning at the last assigned incident halfedge. Ordered connected lists, BFS parents and ribbon output require this exact order. Flat smoothing/color/dynamics use edge insertion order instead; a single generic adjacency cache would conflate these semantics.

G06: Construction/copy/install allocation candidates

verified-source · proposed priority 4

G07: All flat edits invalidate topology; raw writes escape tracking

verified-source · proposed priority 4

Position, attribute and raw-pointer access all use edit(), resetting backend. Finer revisions or retained topology require authoritative read/write ownership and pointer alias tests; no new lifetime guarantees should be promised.

G08: BFS duplicate scans and dense eccentricity computation

verified-source · proposed priority 5

BFS scans complete output and next-level vectors for duplicates; membership stamps can preserve first discovery order after the synchronization boundary is resolved. Eccentricity allocates N*N ints and performs cubic Floyd-Warshall, INF=99999. At V=500001 the distance matrix alone is ~1.0 TB decimal; do not run this case. BFS eccentricity replacement is a separate algorithm proposal with disconnected/long-distance/self-edge compatibility gates.

Compatibility boundaries

  • Edge ID follows insertion pairs; fresh halfedges are 2e (a→b) and 2e+1 (b→a). Edge getVector returns a−b; even halfedge getVector returns b−a. Halfedge getVertices returns head then start. Preserve all three contracts.
  • Genuinely ordered: connected fan APIs, BFS discovery/parents, prev/next/sym, graph ribbon normals/directions and polygon field walks. Simple counts/attributes/endpoints/lengths do not need angular topology. Flat average/color/dynamics require current edge-insertion summation, not cyclic order.
  • Graph onBoundary means halfedge face==-1; degree-one endpoint constraints in average/dynamics are separate. Isolated connected queries currently throw; optimization must preserve that exception. Supported flat duplicates/self edges do not prove safe cyclic traversal for every geometric degeneracy.
  • Graph has no stored face/vertex normal arrays; planar sort normal and ribbon cross-product normals are the applicable paths. Public create(normal) currently does not configure lazy topology. Do not silently correct it.
  • Flat defaults are red vertex color/weight 1 and black alpha-one edge color/weight 2; topology temporary defaults differ and are overwritten. Same-size set retains attributes; sync temporary storage defaults may differ when source attrs are incomplete. Preserve this state-dependent behavior.
  • Object copy retains backend and dirty flags; getDuplicate creates compact flat graph. Retained raw flat versus backend pointers have distinct invalidation hazards. No cache may assume edits stop after a raw pointer return.
  • Viewer selectedGraphSnapshot reconstructs connectivity from point/line positions before world transform and explicitly rejects coincident vertices. Preserve this error/UI contract; a kernel duplicate-position optimization must not introduce a viewer selection fix.
